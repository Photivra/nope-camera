Assistant Access

Design version: 1.0.0, direction B · Reach. Proposed 2026-11-18 for issue 82; not yet accepted. The wording is a draft for the Honesty review. The behavior, the assumptions to confirm on a device, the tests and the decisions are in assistant-access.md.

One setting in Settings › Privacy decides whether Siri, Shortcuts and other assistants on the device may use the app’s actions, and whether the app asks first. It is off on a fresh install. When it is on, each action is named and confirmed before it runs, unless the person chooses otherwise.

  • Off until the person turns it on. With access off, every request is refused and nothing changes.
  • One check, inside every action, at run time.
  • An assistant gets one sentence about what happened. Never a photo, a location or a photo’s details.
  • No assistant action changes a Privacy setting.
  • The app shows what an assistant did, and what it refused. Nothing about it is written to disk.
  • Q does not change: no tile, and no action that opens or edits it.

The setting

The row and the page

Light, night mode, right to left, the largest text size

Asking first

The question is the system’s confirmation, so it is spoken by Siri and looks the same in Shortcuts. It is shown before the app opens. A confirmation covers one run with the values it names and is never remembered.

On the camera

An action that ran is shown as a hint with the sentence the assistant got. Refused requests are shown the next time the camera is on screen. A tip appears once, after five confirmed requests.
