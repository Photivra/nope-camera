## `CameraModel`

public, declared in `Sources/NopeCore/CameraModel.swift`

```swift
@MainActor final class CameraModel
```

The camera's state machine: the single object an interface talks to.

An interface observes ``state``, ``selectedLens``, ``captureFormat``, ``sessionStatus`` and
``captureStatus``, and sends ``CameraIntent`` values through ``send(_:)``. It also runs
``observeEvents()`` for as long as it is visible. The model asks its ``CaptureBackend`` for
facts and decides the next state; the interface holds no rules of its own (AGENTS.md, "One
direction of flow").

The model is isolated to the main actor, so an interface can read its properties directly.

An opaque handle to the live camera feed, for the view that shows the viewfinder.

`NopeCore` can't show video: it imports only Foundation. A ``CaptureBackend`` hands out a
preview source through ``CaptureBackend/previewSource``, and the app target, which knows the
concrete type, turns it into a view (for the AVFoundation backend, a view backed by

inside the handle (AGENTS.md, "Architecture: interface separate from logic").

The live preview is processed by the system; it is a framing guide, not the photo.

## `CaptureBackend`

public, declared in `Sources/NopeCore/CaptureBackend.swift`

```swift
protocol CaptureBackend : Sendable
```

The hardware side of the camera, as seen by ``CameraModel``.

`NopeCapture` implements it with AVFoundation on a device. Tests, previews and the
development build use ``SimulatedCaptureBackend``. Keeping the hardware behind this protocol
lets every rule in `NopeCore` be tested without a camera (AGENTS.md, "Full test coverage").

A backend never decides formats or policies: ``CameraModel`` sends it a ``CaptureRequest``
that says which lens and which format to use.
