## `CameraScreen`

public, declared in `Sources/NopeUI/CameraScreen.swift`

```swift
@MainActor struct CameraScreen<Viewfinder> where Viewfinder : View
```

The camera screen: renders a `CameraModel` and sends it intents.

The screen holds no rules: it shows the model's state and sends `CameraIntent` values
(AGENTS.md, "One direction of flow"). It uses the dark appearance, because a camera is used
in every light and a dark frame doesn't change how a scene looks; other screens follow the
system appearance.

The live viewfinder comes from the app target: `NopeUI` can't show camera video, so the app
passes a closure that turns the model's `CameraPreviewSource` into a view (for example one
backed by `AVCaptureVideoPreviewLayer`).

```swift
CameraScreen(model: model) { source in
    MyPreviewView(source: source)
}
```

## `FormatBadge`

internal, declared in `Sources/NopeUI/FormatBadge.swift`

```swift
@MainActor struct FormatBadge
```

Says what the next photo will be: single-frame RAW, or the labeled processed fallback.

The wording is an honesty claim, so it lives in `Honesty.xcstrings` (AGENTS.md,
"Honesty wording is kept apart"). Teal marks only a fact the camera reported (the lens gives
Bayer RAW); the fallback uses a warning symbol and a plain explanation. Each status has text
and a symbol, never color alone. The badge has a solid backing over the viewfinder.

## `StatusMessageView`

internal, declared in `Sources/NopeUI/StatusMessageView.swift`

```swift
@MainActor struct StatusMessageView<Actions> where Actions : View
```

A centered message with a symbol, a title, an explanation and optional actions.

Used for the permission and no-camera states. It is built from plain `Text`, `Image` and
`Button` views rather than `ContentUnavailableView`, because that view's symbol keeps a fixed
size and fails the accessibility audit's Dynamic Type check. At large text sizes the content
scrolls instead of being clipped (AGENTS.md, "Larger Text").
