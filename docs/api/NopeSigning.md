## `PerPhotoSigner`

public, declared in `Sources/NopeSigning/PerPhotoSigner.swift`

```swift
struct PerPhotoSigner
```

Signs each photo with a fresh key that is never reused.

Privacy rule: a new key for every photo means no two photos can be linked through their
signatures (AGENTS.md, "Honesty"; issue #1, "Signing"). The signer keeps no reference to any
key after ``sign(_:)`` returns.

## `PerPhotoSigner/sign(_:)`

public, declared in `Sources/NopeSigning/PerPhotoSigner.swift`

```swift
func sign(_ data: Data) throws(SigningError) -> SignedData
```

Signs one photo's data with a newly created key.

- Parameter data: The bytes to sign, for example a C2PA claim.
- Returns: The signature and the public key that verifies it.
- Throws: ``SigningError/keyCreationFailed`` if no key could be created, or
  ``SigningError/signingFailed`` if the key couldn't sign. Interfaces present both as
  "not signed", which is a warning that is never hidden.

## `PerPhotoSigningKey`

public, declared in `Sources/NopeSigning/PerPhotoSigningKey.swift`

```swift
protocol PerPhotoSigningKey
```

A P-256 private key that signs one photo and is then discarded.

In the app it is a Secure Enclave key (`SecureEnclave.P256.Signing.PrivateKey`, see
`SecureEnclaveSigningKey.swift`); tests use CryptoKit's software key. The C2PA signer callback
expects a DER-encoded ES256 signature (docs/research/c2pa-signing.md, "Signing with a Secure
Enclave key").
