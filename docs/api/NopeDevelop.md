## `CoreImageRAWRenderer`

internal, declared in `Sources/NopeDevelop/CoreImageRAWRenderer.swift`

```swift
struct CoreImageRAWRenderer
```

Renders a Bayer DNG with Core Image's RAW filter, neutrally.

Needs a real Bayer DNG, which a unit test can't create (ImageIO and Core Image don't decode
a hand-built DNG in the Simulator), so this thin adapter is excluded from the coverage gate
and verified on a device, and with a real DNG in the Simulator by an opt-in test
(docs/TESTING.md, "Developed looks"). Its choices, from the `CIRAWFilter.h` documentation of
each property:

- Noise reduction (luminance and color), sharpening, detail, moiré reduction, local contrast
  (`contrastAmount`, "local contrast to apply to the edges") and local tone mapping are set
  to 0 where the filter supports them (issue #1, "Formats").
- Lens correction is off: the pixels are never corrected (`docs/PRIVACY.md`).
- The tone follows the `DevelopedLook`: `boostAmount` is 1 ("full global tone curve", the
  filter's default) for `DevelopedLook.standard`, and 0 ("no global tone curve, i.e. linear
  response") for `DevelopedLook.flat`. `boostShadowAmount` "has no effect if the
  boostAmount is 0".
- Everything else (white balance, color matrices, highlight recovery, baseline exposure)
  keeps the filter's defaults for the file.
- The output is upright (the filter applies the DNG's orientation by default), rendered at
  16 bits per channel in Display P3, the color space the camera reports; encoding applies
  Display P3's standard transfer function.

## `ImageIOReadBack`

public, declared in `Sources/NopeDevelop/ImageIOReadBack.swift`

```swift
struct ImageIOReadBack
```

The read-back for every finished file: the project's own tag reader plus ImageIO's view of
the file (AGENTS.md, "Fail closed").

`MetadataFileReader` (in `NopeCore`) lists every tag, block and property from the bytes.
ImageIO then opens the file the way Photos and other apps will: it must hold exactly one
image of the expected type, and every key in its property dictionaries is reported, so a
value ImageIO understands but the byte reader files elsewhere is checked too.

## `PhotoEncoder`

internal, declared in `Sources/NopeDevelop/PhotoEncoder.swift`

```swift
enum PhotoEncoder
```

Encodes a developed image as HEIF or JPEG with the system encoders, with exactly the
metadata it is given.

The image comes from the RAW developer and carries no metadata of its own, so the file holds
only the property dictionary `MetadataPlan` built from the allowlist, plus what ImageIO
adds to describe the image itself (checked by the read-back). No thumbnail is embedded
(`kCGImageDestinationEmbedThumbnail` is `false`). HEIF uses the system HEIF encoder only
(AGENTS.md, "Encoders"); a 16-bit image is written as 10-bit HEIF (`Depth` reads back as 10
with ImageIO on macOS 27 and the iOS 27 Simulator).

## `RAWDeveloper`

public, declared in `Sources/NopeDevelop/RAWDeveloper.swift`

```swift
struct RAWDeveloper
```

Develops HEIF and JPEG files from a RAW photo, with metadata built from the allowlist.

The RAW is rendered neutrally (``CoreImageRAWRenderer``: no noise reduction, sharpening or
local tone mapping; issue #1, "Formats") and encoded with the system encoders
(``PhotoEncoder``, ``EncodingSettings``). The new file's metadata is built by
`MetadataPlan` from the DNG's own properties, which already passed through the allowlist
at capture, and its orientation is 1 (up) because the rendered image is upright.
