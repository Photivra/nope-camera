## [Unreleased]

### Added
- Settings, opened from a Settings button on the camera screen in every state (a native `Form` in a sheet): formats (RAW, HEIF, JPEG; RAW and HEIF by default; at least one; RAW shown as unavailable on a device without it; the HEIF and JPEG look, Standard or Flat, shown while HEIF or JPEG is selected), Privacy (the "Remove all optional details" master switch, on by default, a switch for each optional metadata item with what turning it off costs, the signing switch, on by default, and the locked items with their reasons), manual controls (off by default), "Start in clean view" (off by default), the Honesty screen and About. Manual controls take effect when the manual controls read the switch.
- `NopeCore`: `NopeSettings`, stored in the app's own `UserDefaults` on the device only. It holds `SaveSettings` (formats, the HEIF and JPEG look, metadata and signing; passed to the camera model for the next photo), manual controls and clean view, with `LockedMetadataItem` for the locked items. The privacy manifest declares the `UserDefaults` required-reason API (`CA92.1`).
- Honesty screen: what nope. never does (no network, no data collected, how to check with App Privacy Report, the RAW is never changed by the HEIF and JPEG look), what iOS may still do (iCloud Photos, Enhanced Visual Search, analysis in Photos, Share with App Developers, sharing from Photos), and what no app can remove (the sensor noise pattern, App Store builds versus the source), worded as in `docs/research/privacy-claims.md`.
- About and licenses: version, the GPL-3.0-only license text, the project notices with the Adobe DNG notice, the trademark statement, and the source address as a link that opens in the system browser when tapped.
- New strings in eleven languages (AI translations, needs review); the privacy, signing and Honesty wording is in `Honesty.xcstrings` and needs a fluent human review before release.
- UI tests with accessibility audits for every settings screen, at the default and largest text sizes and in right-to-left layout.
- C2PA Content Credentials signing (`NopeSigning`): `ContentCredentialsSigner` signs a DNG, HEIF or JPEG with a new P-256 key for every file (Secure Enclave on a device; a software key compiled for the Simulator only), an anonymous self-issued certificate, and a manifest with one `c2pa.created` action and "Photivra Nope Camera" as the claim generator and in the certificate name. Fully offline: no timestamp authority, OCSP, remote manifest or trust list. Validators report the file as valid and the signer as untrusted, which is expected. Not yet called by the app: the save pipeline comes next.
- The app signs every saved file when the signature switch is on (`MetadataSettings.signsPhotos`, on by default): `ContentCredentialsSigner` implements the `PhotoSigning` hook, and signed files pass the same read-back as unsigned ones. If signing fails, the photo is saved unsigned and the status says so.
- Debug builds: a `signingFails` simulated scenario (and a simulated signer for the others), with a UI test and accessibility audit for "Saved. Not signed: the signature couldn't be created."
- Network-free C2PA library: c2pa-rs 0.92.0 built from source with every network feature off (`scripts/build-c2pa-lib.sh`, inputs pinned in `c2pa-lib/`, Rust 1.99.1), published as a checksummed release asset (`c2pa-lib-v0.92.0`); the c2pa-swift 0.1.0 wrapper vendored without its networking code (`Vendor/c2pa-swift`). CI rebuilds it on every pull request, checks its checksum against the pin, reviews every Rust crate's license with cargo-deny, and checks the library, a linked iOS binary and the app for networking code (`scripts/check-no-networking.sh`).
- Dependencies: swift-certificates 1.21.1, swift-asn1 1.7.4 and swift-crypto 4.5.2, pinned exactly; listed in `THIRD_PARTY.md`.
- Docs: `docs/PRIVACY.md`, "Content Credentials" (what a signature contains and what it adds to each format), and `docs/TESTING.md`, "Checking signatures".
- Manual and pro controls, behind the "Manual controls" option (off by default; full auto stays the default). `NopeCore`: `ManualControlsModel` (`CameraModel.manual`), `ManualControlIntent` (`CameraIntent.manual`), a per-lens `ManualCapabilities` model, `ControlScale` (one-third-stop ISO and shutter values within each lens's real range, ±3 EV compensation, relative focus, 2500–10,000 K white balance with tint and presets), P, S, I and M exposure modes (S and I only where iOS 27 reports them for the lens's format), center, spot and whole-frame metering (spot and whole frame need iOS 26), AE-L and AF-L, "All Auto", exposure bracketing (3, 5 or 7 frames, ⅓ to 2 EV, each a separate single-frame photo through the system's manual exposure bracket, saved as its own photo) and interval shooting (separate photos; the timer runs only while a series runs on the camera screen). `NopeCapture`: `AVFoundationCaptureBackend` applies the controls with `lockForConfiguration`, custom exposure, locked focus at a lens position and locked white balance gains, limited again to the active format's ranges, and reports the values in use (exposure offset, ISO, shutter, focus, aperture, white balance) at most four times a second from key-value observation, only while manual controls are on; no video data output is added. Camera screen: an EV meter, the exposure mode picker, a six-slot grid in a fixed order (each slot a VoiceOver adjustable element with Auto/Manual and "All Auto" actions), one panel per control with native sliders and pickers, Pro Tools, and a list with steppers at accessibility text sizes. New strings in eleven languages (AI translations, needs review); the bracketing and interval wording is in `Honesty.xcstrings`.
- Clean view: the eye button, or a swipe down on the viewfinder, hides every control except the shutter; a swipe up, the button, or the shutter's "Show Controls" VoiceOver action brings them back. The no-RAW badge, a running interval series and capture results stay visible.
- Debug builds: a `manual` simulated camera scenario, with UI tests and accessibility audits for the grid, panels, modes, a fixed aperture, Pro Tools, bracketing, interval shooting, clean view, the largest text size and right-to-left layout.
- Saving to Photos: each photo's metadata is built from the allowlist in `docs/PRIVACY.md` (never by deleting known tags), every file is read back with the project's own tag reader (TIFF/DNG, JPEG, HEIF, XMP) and ImageIO, and a file with any tag, block or value off the allowlist, or a changed RAW image, is not saved (fail closed). Add-only Photos access; a RAW and its HEIF are one Photos asset with the RAW as the original. Formats RAW, HEIF and JPEG, RAW plus HEIF by default.
- `NopeCore` settings model: `SaveSettings` (formats) and `MetadataSettings` (the "Remove all optional details" master switch, one switch per optional item, name and copyright, and the signature switch).
- DNG metadata written through AVFoundation's replacement metadata, so the sensor data isn't re-encoded; HEIF (10-bit) and JPEG developed from the RAW with Core Image (no noise reduction, sharpening or local tone mapping), in a Standard look (one global tone curve, the default) or a Flat look (no tone curve; `SaveSettings.developedLook`, `DevelopedLook`), and encoded with the system encoders. With the app name switch on, `Software` reads "Photivra Nope Camera" and the version.
- A signing hook (`PhotoSigning`) before the read-back.
- Capture status: "Saving…", "Saved and signed." or "Saved. Not signed:" with the reason, and plain messages when a photo isn't saved. New strings in eleven languages (AI translations, needs review); signature and privacy wording in `Honesty.xcstrings`.
- Metadata tests for all 8,192 switch combinations in every format, fail-closed fuzz tests with a simulated future system tag, and UI tests for the rejected and Photos-denied states.

- Stuck-camera detection: every RAW photo's pixel buffer is sampled (128 bytes), and a blank (zero-filled) photo is dropped. nope. restarts the camera once and retakes the photo; if it is still blank, the camera screen says "The camera isn't sending a picture." and disables the shutter. New strings in eleven languages (AI translations, needs review).

### Removed
- The "Captured (not saved yet: development build)" status.

### Changed
- The "Manual controls" option and "Start in clean view" are `NopeSettings` values that the app sends to the camera model (`.manual(.setEnabled(_:))`, `.setCleanView(_:)`); `ManualControlsSetting` is removed, and a stored value under its old key is migrated once.
- `CameraScreen` takes the person's `NopeSettings` (`CameraScreen(model:settings:viewfinder:)`).
- `NopeSigning`: `PerPhotoSigner`, `SignedData` and `SigningError` are replaced by `ContentCredentialsSigner` and `PhotoSigningError`; `PhotoFile` records whether the phone's camera processed it (`isProcessedByDevice`), so the manifest describes the fallback truthfully; `PerPhotoSigningKey` now provides the certificate key instead of a DER public key.
- Architecture check: `NopeSigning` may also import `X509` and `SwiftASN1` (swift-certificates), to build each file's certificate.
- `Lens` describes its Bayer RAW format (`bayerRAWFormat`) instead of a flag, and carries its capabilities.

### Fixed
- The Debug tag check now captures through the app's own capture backend and its single session, switching lenses through the backend, with no session or video data output of its own. It no longer writes a metadata-stripped DNG or a preview frame.
- Testing docs: the blank frames in the first device runs came from a Mac viewing and controlling the phone's screen, which blanks the camera picture for apps other than Apple's Camera; stopping that session fixed them (docs/TESTING.md, "Black frames"). The tag check on 2026-11-12 produced real images on every lens and confirmed the exposure tags (docs/PRIVACY.md).
- Stopping the camera now tears the session down in order: `stopRunning()` on the session queue, then every input and output removed, before anything can start it again. The camera probe does the same.
- Black frames in the tag check: the capture setup now follows the documented order (switches and an explicit photo size committed before the session starts, zero shutter lag and responsive capture off, the output prepared for RAW, captures gated on `captureReadiness`, file types named). Both the app's backend and the tag check use it. To be confirmed on a device.
