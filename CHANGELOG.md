# Changelog

All notable changes to this project are documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [semantic versioning](https://semver.org).

## [Unreleased]

### Added
- Settings presets (issue #72): save every current setting under a name ("Astro", "Bugs at night"), apply it with one tap from Settings (Presets, the first row) or from Presets in the quick-controls tray, rename and delete presets, and return everything to a fresh install's settings with the built-in Factory Defaults, which keeps saved presets. A preset holds every stored setting (formats, file options, pairing, privacy, signing, location, mirroring, overlays, flash, night mode, and any setting added later) and the camera's lens, manual exposure values, Close-Up, drive mode, bracket, interval series and astro helper. Applying shows what happened, with notices (Location stays off when location access isn't allowed, no matching lens, values moved into the lens's range) and Undo. Presets are stored on the device only, with the settings, and aren't passed to the Lock Screen camera. `NopeCore`: `SettingsPresets`, `SettingsPreset` (versioned, forward-compatible encoding), `PresetChoice`, `PresetNotice`, `PresetApplyResult`, `PresetNameProblem`, `CameraSetup`, `CameraModel.cameraSetup`, `applyCameraSetup(_:manualControlsOn:)` and `isBusyForPresets`. UI tests with accessibility audits (the largest text size, right-to-left, night mode). New strings in eleven languages (AI translations, needs review; the privacy notes are in `Honesty.xcstrings`).
- Shared settings and a Night Mode control (issue #42): the person's settings are kept in the `UserDefaults` of the app's App Group (`group.$(NOPE_BUNDLE_IDENTIFIER)`, `NOPE_APP_GROUP_IDENTIFIER` in `Config/Base.xcconfig`), shared by the app and its controls, and moved there once from the app's own `UserDefaults`. A Night Mode switch for Control Center and the Lock Screen (`NightModeControl`) reads and writes the same setting; the app follows a change at once through a Darwin notification, without polling, and refreshes the control after its own changes. The Lock Screen camera, which Apple doesn't let use an App Group, now starts with a copy of the person's settings (formats, details, signing, night mode and the rest) from the "Open nope." intent's app context instead of the defaults; its changes last until it closes, and it still has no location or storage and battery reader. `NopeCore`: `SharedSettingsStore`, `SettingsChangeSignaling`, `DarwinSettingsChangeSignal`, `SharedSettingsSync`, `NopeSettingsSnapshot`, `NopeSettings.reload()`, `makeSnapshot()` and `apply(_:)`. Entitlement `com.apple.security.application-groups` allowlisted; privacy manifests declare `1C8F.1`. To be verified on a device.
- Siri and Shortcuts, more actions (issue #62): Take Photo has a Number of Photos (1 to 50; more than one takes a burst of exactly that many separate photos with the burst's own loop, whatever the drive mode); Switch Lens, Turn On the Light and Start Interval Shooting (optional seconds between photos and number of photos; needs Manual Controls on, and says so otherwise) open the app; Turn Off the Light and Stop Interval Shooting run without opening it. Siri phrases "Open the camera in nope.", "Switch to Ultra Wide in nope.", "Turn on the light in nope.", "Turn off the light in nope.", "Start interval shooting in nope." and "Stop interval shooting in nope." in eleven languages. Siri can't take a photo on a locked device: the app needs unlocking, and the Lock Screen camera extension can't receive requests (docs/ARCHITECTURE.md). `NopeCore`: `ShortcutRequest.selectLens`, `.setLight`, `.startInterval`, `.stopInterval` and `outcomeWithoutCameraScreen`, `PhotoShortcut.count`, `IntervalShortcut`, new `ShortcutOutcome` cases, `ShortcutInbox.isServed`, `BurstEnd.countReached`. Debug builds: `-NopeSimulatedShortcut burst<count>` and `lens-ultraWide`, with UI tests. New strings in eleven languages (AI translations, needs review).
- Lock Screen, Control Center and Action button (issue #42): an "Open nope." control (WidgetKit control extension `NopeControls`, with the `CameraCaptureIntent` `OpenCameraIntent`) opens the camera; on a locked device the system opens the Lock Screen camera (`NopeCaptureExtension`, LockedCameraCapture), which uses the same capture and save pipeline as the app (RAW, the metadata allowlist and read-back, a signature per photo, add-only saving) and keeps its own settings, starting from the defaults. Both extensions have privacy manifests and no networking code (CI checks their binaries too). To be verified on a device.
- Siri and Shortcuts (issue #62): Take Photo (opens the app; no delay, 3 or 10 seconds, or a custom delay up to a minute through the self-timer and its countdown; optional lens) and Set Night Mode (on or off, without opening the app). Siri phrases such as "Take a photo with nope." and "Take a photo in 10 seconds with nope." in eleven languages. Siri says only whether the photo was saved and signed, or why not. `NopeCore`: `ShortcutInbox`, `ShortcutRequest`, `PhotoShortcut`, `ShortcutOutcome`, `CameraUnavailability` and `CameraModel.serveShortcuts(from:)`. Debug builds: `-NopeSimulatedShortcut <seconds>` with UI tests. `scripts/check-localization.sh` checks App Shortcuts phrase sets. New strings in eleven languages (AI translations, needs review).
- Astro helper (issue #60), in the quick-controls tray on lenses with Bayer RAW, manual exposure and manual focus: a run of single Bayer RAW frames of the night sky, for stacking in other software; the app never stacks, merges or processes them, and each frame goes through the same allowlist, read-back and signature as any photo. Turning it on turns night mode on, turns manual controls on (off again with the helper if it turned them on), and sets focus to the far end and the longest shutter and highest ISO the lens reports, which stay the person's to change; the light stays off. The shutter starts a 3 or 10 second self-timer (10 by default), then takes 5 to 300 frames (20 by default) back to back, with "Frame 3 of 20" and Stop Frames; the screen stays awake and dims while they run. A run stops before storage runs out, at 10% battery unplugged, when the camera stops or at a failed frame, and keeps every frame taken. Astro Settings shows the frame count, start delay, each frame's exposure, the total exposure time and an upper storage estimate. An Astro pill turns it off. It isn't offered in the Lock Screen camera, which can't read storage and battery (`DeviceStatus.canRead`). `NopeCore`: `AstroModel` (`CameraModel.astro`), `AstroIntent` (`CameraIntent.astro`), `AstroExposure`, `AstroEstimate` (`CameraModel.astroEstimate`), `BurstEnd.batteryLow`, `DeviceStatus.isBatteryBelow(_:)`. Burst frames now carry the location when the Location switch is on, as single photos do. Debug builds: an `astro` simulated scenario and `-NopeSimulatedViewfinder target`; UI tests with accessibility audits (night mode, the largest text size, right-to-left). New strings in eleven languages (AI translations, needs review; the frames statement is in `Honesty.xcstrings`).
- Comparison shot (issue #55): Compare in the quick-controls tray (off at launch; a pill while on) follows each single or self-timer photo with a second photo with the phone's processing at its highest setting for apps (`.quality` prioritization, which can combine frames), and opens a compare view: both pictures lined up with a divider (slider, VoiceOver adjustable, nope. Only / Split / Phone Only, pinch and zoom buttons), what each side is, and a Details list of both files' metadata grouped as only in the phone's version, different, only in the app's file and the same, with each item's privacy setting and identifying values hidden until Show Value. If the second photo fails, the app's photo is still saved and the view says so. The app's own photo is taken exactly as before. `NopeCore`: `ComparisonModel` (`CameraModel.comparison`), `ComparisonIntent` (`CameraIntent.comparison`), `ComparisonCaptureBackend`, `PhoneProcessedPhoto`, `PhotoComparison`, `MetadataComparison`, `CameraModel.comparisonAppliesToNextPhoto`. Honesty screen statement. Debug builds: a `comparisonFails` scenario. New strings in eleven languages (AI translations, needs review).

- Drive, in the quick-controls tray: single photo (the default), a 3 or 10 second self-timer, or burst (issues #39 and #46). A burst takes single frames as fast as the camera is ready, each saved as its own photo through the same allowlist, read-back and signature as any photo (nothing merged); each frame is saved while the next is taken, so memory stays bounded; it stops when the shutter is pressed again or Stop Burst, at 50 frames, before storage runs out, when the camera stops, or at a frame that can't be saved, and frames already taken are still saved. A pill shows the self-timer or burst, and returns to single photos. `NopeCore`: `DriveModel` (`CameraModel.drive`), `DriveMode`, `DriveIntent` (`CameraIntent.drive`), `Countdown` with `.drive(.startTimer(seconds:))` for any delay, `CaptureStatus.savedBurst`, and `CameraModel.canPressShutter`.

- Storage and battery warnings (issue #44): an amber "Storage Low" chip says about how many photos still fit when fewer than 25 do, "Storage Full" says the next one won't fit, and "Battery Low" shows at 20% or less while unplugged (with a note when Low Power Mode is on); each is announced to VoiceOver. Fully offline: no timestamp authority, OCSP, remote manifest or trust list. Validators report the file as valid and the signer as untrusted, which is expected. Not yet called by the app: the save pipeline comes next.
- The app signs every saved file when the signature switch is on (`MetadataSettings.signsPhotos`, on by default): `ContentCredentialsSigner` implements the `PhotoSigning` hook, and signed files pass the same read-back as unsigned ones. ### Fixed
- A RAW saved with a HEIF or JPEG wasn't saved on a device ("Not saved: the photo library couldn't add the photo."): PhotoKit rejects a RAW pair whose alternate (the processed copy) is added from memory, with `PHPhotosErrorDomain` 3300, on every lens and with either pairing (measured in the iOS 27.2 Simulator). The alternate is now added from a file written with complete file protection, moved into Photos and deleted as soon as the save ends; if the file can't be written, the pair is saved as two photos. Every other file still goes from memory to Photos. A failed save logs the error's domain and code, marked private, without showing technical text. `NopeCapture`: `PhotoKitMapping.prepare(_:stage:)`, `ResourceStaging`. Unit tests check that every format combination and pairing gives requests PhotoKit accepts.
- Turning night mode or Red Viewfinder on or off no longer rebuilds the live viewfinder. With natural colors the viewfinder moved from the camera view to behind it, so each switch made a new `AVCaptureVideoPreviewLayer`, which attaches to the running capture session on the main thread, and the camera froze for a while on a device. `CameraScreen` now always draws the one viewfinder behind the interface (`ViewfinderFrame`), and Red Viewfinder only tints it; the capture session isn't touched. Unit tests (`NightModeViewfinderTests`) check that the viewfinder is made once and the session never restarts; a UI test checks the viewfinder still follows the picture in the scrolling layout.
- With "Lens make and model" on and a HEIF or JPEG selected, no photo was saved: ImageIO reports a DNG's lens tags again under `{ExifAux}`, the developed copy copied them, and ImageIO wrote them as XMP `aux:` properties that the read-back rejects. A HEIF or JPEG now never gets `{ExifAux}` values; the same lens values are still in its EXIF `LensMake`, `LensModel` and `LensSpecification` (`MetadataPlan.isWritten(_:in:)`). Found by the file compatibility matrix; regression tests in `NopeCoreTests` and `NopeDevelopTests`. To be confirmed on a device.
- The focus magnifier now enlarges the viewfinder in night mode with natural colors too (it had no effect there, and focus peaking was enlarged out of line with the picture), with a UI test for both night-mode viewfinders.
- RAW photos weren't saved on a device (issue #65): AVFoundation writes no DNG unless the replacement metadata's `{TIFF}` dictionary has `DateTime`, `Make`, `Model` and `Software` (measured on an iPhone 16 Pro Max with iOS 27.2.1). Every DNG now carries all four: the real value when the item's switch is on, an empty text when it is off (never a placeholder). The read-back accepts an empty value in every encoding, or the tag left out, and nothing else when the switch is off. Regression tests for all 8,192 switch combinations. To be confirmed on a device.
- A signed DNG couldn't be opened by iOS (issue #66): the C2PA library's own DNG writer moves IFD0 to the end of the file, and ImageIO then reports a plain TIFF with no image. The app now inserts the Content Credentials entry (tag 52545) into IFD0 in place, appends the store, and signs with the C2PA library's data-hash workflow (`DNGManifestSlot`, fuzz-tested). Signed DNG, HEIF and JPEG files open in ImageIO as their own type with one image and validate with the C2PA library's reader and c2patool. To be confirmed on a device.
- With both the app name and the iOS version switches on, a HEIF or JPEG developed from the RAW would have had a nested `Software` value ("Photivra Nope Camera 0.2.0 (Photivra Nope Camera 0.2.0 (27.2.1))"), because it was built from the DNG's value as if the system had written it. The system version is now taken back out of that value, and every format gets exactly the agreed value; regression tests across formats and switch combinations.
- A signed file that fails the read-back is never saved: the unsigned file, which passed first, is saved instead, with "Saved. Not signed: the signed file didn't pass the check." (`SignatureStatus.UnsignedReason.signedFileFailedCheck`; a `signedFileRejected` Debug scenario with a UI test and accessibility audit; new string in eleven languages, AI translations, needs review).
- Flaky checks (issue #59): the coverage gate's occasional uncovered region came from non-atomic coverage counters under parallel tests; CI and `docs/TESTING.md` now build coverage with atomic counter updates. `CaptureReadinessTests` have a timeout no runner can reach, and the largest-text blank-picture audit waits until the layout stops moving.
- The Debug tag check now captures through the app's own capture backend and its single session, switching lenses through the backend, with no session or video data output of its own. It no longer writes a metadata-stripped DNG or a preview frame.
- Testing docs: the blank frames in the first device runs came from a Mac viewing and controlling the phone's screen, which blanks the camera picture for apps other than Apple's Camera; stopping that session fixed them (docs/TESTING.md, "Black frames"). The tag check on 2026-11-12 produced real images on every lens and confirmed the exposure tags (docs/PRIVACY.md).
- Stopping the camera now tears the session down in order: `stopRunning()` on the session queue, then every input and output removed, before anything can start it again. The camera probe does the same.
- Black frames in the tag check: the capture setup now follows the documented order (switches and an explicit photo size committed before the session starts, zero shutter lag and responsive capture off, the output prepared for RAW, captures gated on `captureReadiness`, file types named). Both the app's backend and the tag check use it. To be confirmed on a device.
